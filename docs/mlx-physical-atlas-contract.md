# Apple-Silicon MLX Determinism Atlas physical-observation contract

This schema defines how future model-free MLX observations must be identified, ordered, compared,
and held in custody. It performs no observation. It does not install, import, load, query,
synchronize, or execute MLX, MLX-LM, or Metal, and it makes no measured-behavior claim.

The exact study is `apple_silicon_mlx_determinism_atlas_physical_v1`, study ID
`sha256:b4bbd2bdcaa0d5ad4d40cd60918fe0466f68a724ed858246d6e060543154a78d`.

## Relationship to the inert canary

The existing schema-1.0 canary remains historically unchanged:

- 48 prospective operation/dtype/evaluation cells;
- exactly eight represented synthetic cells;
- 40 prospective-only cells;
- zero accepted physical MLX or Metal observations.

The physical study is a versioned successor subset with new cell and record identities. It does
not rename, promote, or rewrite a canary cell, fixture, result, comparison, or atlas identity. Its
inspection output always reports the legacy 48 prospective, eight synthetic, and zero accepted
physical counts separately from its 18 selected cells.

## Selected v1 cells

The bounded first study covers model-free primitives used directly in transformer computation:

| Operation v1 | Shape and axes | Selected dtype/mode cells |
|---|---|---|
| Matrix multiplication | `[4,8] @ [8,4] -> [4,4]`, contracted axes 1/0 | `float16` eager, `bfloat16` eager, `float32` eager and compiled |
| Softmax | `[2,4,8]`, axis 2, keepdims | `float16` eager, `bfloat16` eager, `float32` eager and compiled |
| RMS normalization | `[2,4,8]`, axis 2, epsilon exact `float32` bytes `6f12833a` | `float16` eager, `bfloat16` eager, `float32` eager and compiled |
| Layer normalization | `[2,4,8]`, two-pass axis-2 reduction, epsilon exact `float32` bytes `acc52737` | `float16` eager, `bfloat16` eager, `float32` eager and compiled |
| Top-k | `[2,16]`, axis 1, `k=4`, value-descending/index-ascending ties | `float32` eager and compiled |

This yields 18 cells. Integer-only argmax is deliberately deferred: top-k already exercises ranked
selection while preserving a floating value output for the common numerical comparison contract.
Reduction is represented by the fully specified mean, centered-variance, square, and normalization
reductions rather than adding a redundant free-standing sum cell. No selected cell claims current
MLX support.

Every operation has a content identity over its version, mathematical definition, shapes, axes,
layout, supported dtypes, constants, accumulation/evaluation dtype, casting policy, rounding
policy, reduction order, and output contract. Every cell binds that operation identity, its dtype
and eager/compiled mode, and deterministic inputs.

## Deterministic inputs

Inputs use `sha256_domain_separated_finite_codebook_v1`. The UTF-8 seed material, its SHA-256
seed, cell name, input name, and linear element index are domain-separated. The first digest byte
selects one of eight exact finite native-dtype encodings: -2, -1, -0.5, +0, +0.5, +1, +2, or +3.

Each input descriptor binds dtype, shape, row-major layout, little-endian payload length, payload
SHA-256, and the canonical input-set identity. The generated bytes are not MLX outputs and do not
require a runtime.

## Run order and synchronization

For each cell, the future observer must use this exact order:

1. three new cold processes, one observation in each;
2. one new warm process with two non-observation warmups;
3. five ordered observations in that warm process.

There are eight observations, two warmups, zero retries, and no selective reruns per cell. Cells
run in exact study-array order. A compiled cell compiles the exact closed operation once per
process before any warmup or observation; compilation is not an observation.

Every planned step binds:

- input materialization completion before the operation;
- compilation completion before the first operation when compiled;
- operation completion before output readback;
- output-byte materialization before process advance.

Timing is forbidden. Missing, duplicate, or reordered steps and synchronization points invalidate
the envelope.

## Comparison contract

Floating tensors must match dtype, shape, row-major layout, endianness, and element count before
comparison. The report contains:

- exact payload equality and native-element mismatch count;
- maximum absolute and relative error;
- RMS error;
- maximum signed-zero-normalized native-dtype ULP distance;
- finite-pair, finite-mismatch, NaN-pair, infinity-pair, signed-zero-bit-difference, and
  special-mismatch counts.

Errors are exact IEEE binary64 big-endian hexadecimal encodings. Equal signed zeros have zero
numerical and ULP error while retaining a bit-difference count. A minimum subnormal is one ULP
from either signed zero and opposite minimum subnormals are two ULPs apart. NaNs are equal only
when sign and payload match; infinities are equal only when sign matches. Non-finite pairs never
enter finite absolute, relative, RMS, or ULP metrics.

Top-k values use the floating contract. Its `int32` indices require exact shape and payload
equality.

## Identity, provenance, custody, and evidence categories

The study binds reviewed candidate, qualification, target, worker, and authorization slots. The
candidate, static qualification publication, and prospective target identities are pinned. The
worker and authorization identities are explicitly unavailable.

`static_specification`, `synthetic_fixture`, and `physical_observation` are immutable origin
categories. Static or synthetic evidence can never be promoted to physical evidence. A physical
record requires authoritative collector, runtime, device, Metal, worker, authorization, and
process identities plus input snapshot, output root, launch, synchronization, raw-output, and
parent-validation custody receipts. Caller-supplied digest strings are self-asserted, not
authority.

The current compiler emits only `static_specification` / `prospective_unobserved` envelopes. Runs,
comparisons, provenance, and custody are empty. Every envelope is non-promotable and has
`accepted_physical_observation=false`. Physical acceptance remains mechanically impossible while
the reviewed worker/authorization slots and authoritative acquisition compiler are absent.
